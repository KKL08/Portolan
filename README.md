插件名字 Portolan 灵感来自于中世纪远洋航行绘制的航海图，这也是这个插件的设计理念，为 agent 的长程任务导航（在 Claude Code 中使用）。

---

## 长程任务为什么需要 Harness

各家厂商都在提升 agent 长程任务的表现。半年前 agent 自主执行的续航还比较有限，现在已能跨数十轮、持续数小时完成复杂工程。长程自主是公认的下一个能力前沿。

但模型越强、跑得越远，三个结构性问题越突出：

| 问题 | 表现 |
|---|---|
| **目标漂移** | 执行到中段，agent 悄悄把目标改简单或偏离原意 |
| **提前退出** | 没做完的说做完了，中途中断任务 |
| **验证缺失** | 任务执行完成后缺乏可靠的独立验证 |

仅靠模型进步不够——这三件事是结构问题。模型越聪明，跑偏了越难追，提前退出越能自圆其说。

长程任务要可靠完成，模型和 Harness 缺一不可。模型负责执行，Harness 负责管控。

Portolan 是一个 Claude Code 插件，专门强化长程任务中的任务需求确认、持续执行、终态判定和独立验收。

## 安装

> ⚠️ 目前为 **Beta（v0.1.0）** 测试版本：后续迭代中可能会对一些核心功能、流程等进行调整。

Portolan 是 [Claude Code](https://docs.anthropic.com/en/docs/claude-code) 插件，需要 Claude Code 运行环境。

Claude Code 里两步：

```
/plugin marketplace add KKL08/Portolan
/plugin install portolan@portolan
```

另需 Python 3.10+（`state-guard` 用到 `fcntl`，仅 macOS）和 PyYAML。

## 快速上手

一句话发起任务：

```
/portolan:long-horizon-task 你的任务目标和需求
```

Portolan 追问关键问题，敲定成功画像、验收命令，冻结任务清单，派 subagent 执行。跑完后开新会话终审：

```
/portolan:finish
```

## 工作原理

### 分层架构

### 异常信号分诊

```mermaid
graph LR
    M["检测到冻结文件被改动"] --> I{"原始基线<br/>本身可信?"}
    I -->|否 · 基线也被改过| STOP1["转人工核查"]
    I -->|是| D["比对改了哪里"]
    D --> R{"独立盲审<br/>目标改严还是改松?"}
    R -->|改严 / 等价| AUTO["自动放行 · 继续跑"]
    R -->|放宽 / 偏离目标| STOP2["转人工拍板"]
```

### 运行流程

```mermaid
flowchart LR
    A["发起"] --> B["试跑"]
    B --> C["分发"]
    C --> D["编排"]
    D --> E{"终态?"}
    E -->|未完成| F["续跑"]
    F --> D
    E -->|完成| G["终审"]
```

| 阶段 | 做什么 |
|---|---|
| **发起** | 摸底任务、定验收清单、选评估策略、冻结任务清单 |
| **试跑** | 分发前先小范围试跑，验证执行计划可行 |
| **分发** | 组装执行规程，冻结任务清单 |
| **编排** | 状态持久化跨上下文边界，代码判定终态；哈希信号先分诊，等价、收紧自动追认继续跑，放松、改向转人工；中断时带上下文自动恢复 |
| **续跑** | 审批、阻塞、无进展等停点，人来拍板 |
| **终审** | 干净会话盲验 + 程序审计（含追认轨迹审计） |

### 三个入口

| 命令 | 用途 |
|---|---|
| `/portolan:long-horizon-task` | 发起全流程 |
| `/portolan:continue` | 停点续跑 |
| `/portolan:finish` | 终审验收 |

**`/portolan:long-horizon-task`** — 主入口，负责全流程发起。收到任务后先摸底，判断是否需要长程装备，追问关键问题和你对齐任务目标和验收标准，确认验收命令，签署并冻结任务协议单。之后进入试跑、分发、编排执行和终审验收流程。

**`/portolan:continue`** — 停点续跑。执行中遇到需要审批、被外部阻塞、异常打转等情况，Portolan 会停下来向你报告详细情况。你拍板决策后任务会从原会话暂停点自动继续任务。此指令用于手动发起续跑或者用在新会话冷启动断点继续任务。

**`/portolan:finish`** — 独立终审。开一个**干净会话**，不带执行背景上下文，重跑验收的命令，不采信执行者自报的结果。同时做全盘审计：核对冻结哈希、检查证据完整性、跑 audit-chain 核对追认链衔接和停点窗口，抓漏改与伪造审批。此指令用于用户手动做额外复核审查。

> **finish 可以单独使用。** 即使任务不是 Portolan 发起的，只要有一份任务协议单和验收清单，`/portolan:finish` 就能对它做独立验收。适合给任何 agent 完成的工作加一道隔离复核——换会话、换上下文、亲自跑一遍，比让同一个 agent 自证可靠得多。

### 多层约束与复核

关键流程分层设防、多轮复核，拦截 agent 在长程任务中可能发生的幻觉、越界操作和投机偷懒行为：

- **冻结与篡改保护** — 目标、验收标准等关键文件开工即冻结，判分逻辑、期望答案一起冻住，agent 改不了验收规则。执行期内，hook 拦截常规写路径（Write/Edit/Bash）对冻结文件和 `.frozen/` 快照的写入与删除，重冻结通道同步关闭；若出现绕开工具直接篡改的偶发投机行为，会被下一次校验和终审复盘兜底抓住
- **信号分诊** — 先校验快照有没有被一起动过手脚，再对比 diff，再独立审判定改动方向。等价或收紧的改动自动确认继续跑；刻意放松、偏离核心目标的改动拦截并告知用户。另支持配置 `manual` 模式，所有异常信号一律转用户审核，适合更精细的控制
- **变更提案通道** — 执行者发现目标或方案存在重大问题时，不能直接改冻结文件，只能写结构化提案挂"需批准"，等用户审阅批准后才用 amend-freeze 入账
- **轨迹审计** — finish 跑 audit-chain：核对每条追认的哈希是否逐条衔接、时间戳是否落在停点窗口内、有没有未经用户批准的投机改动、当前基线有没有无主漂移，并给出最初发起任务的基线到当前的全量 diff
- **独立终审** — finish 在干净会话里亲自重跑验收命令，不采信执行者自报

执行交给 Claude Code 原生 subagent，Portolan 只管准备、分发、验收——不造第二套执行引擎。
